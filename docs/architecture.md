# Architecture

Ghostpad is a standalone Rust receiver with compiled-in HTML, JavaScript, CSS, and icons. The phone connects directly over local HTTP/WebSocket or optional HTTPS/WSS. There are no Cargo registry or browser runtime dependencies. System OpenSSL provides TLS, hashing for the WebSocket handshake/CSP, and constant-time credential comparison. SHA-1 is used only for the RFC 6455 handshake, not for stored credentials.

| Boundary | Implementation |
| --- | --- |
| CLI, bounded HTTP routing, controller ownership | `src/main.rs` |
| Private IPv4 selection and validation | `src/network.rs` |
| Persistent pairing key | `src/pairing.rs` |
| OpenSSL and buffered deadline-based I/O | `src/transport.rs`, `src/crypto.rs` |
| Narrow WebSocket framing | `src/wire.rs` |
| Input decoding and Linux uinput | `src/input.rs`, `src/keys.rs`, `src/touchpad.rs` |
| Embedded phone page and CSP hashes | `src/page.rs` |
| Phone interface and gestures | `web/src/`, `web/index.html` |
| Desktop pairing interface | `web/desktop.html`, `web/src/desktop.ts`, `web/src/desktop.css` |
| User installation and input/firewall helpers | `scripts/`, `packaging/` |

The complete phone interface arrives in one response; CSP hashes allow the embedded script/style content. The separate desktop assets add no phone startup payload. Its authenticated HTTP requests retrieve a cached SVG QR generated by `qrencode` over stdin and poll status without taking the controller's WebSocket. It pauses polling when hidden/offline and backs off on failures. Its stop command wakes the blocking listener.

One authenticated phone holds the input mutex until disconnect/error. At most 16 connection workers block on socket input, with bounded read/write deadlines. The uinput backend creates pointer, keyboard, and native multitouch devices. Typed text maps supported ASCII to physical US keys. Dropping the process removes its virtual devices.

Motion uses binary packets over a reliable ordered WebSocket. The acknowledged `ghostpad.flow.v1` subprotocol confirms validated/native input delivery. Browser flow control coalesces movement within bounded queues, reserves capacity for release/control commands, and expires stalled input instead of replaying it after reconnect. The server also accepts the documented legacy unwrapped protocol. See [PROTOCOL.md](../PROTOCOL.md) for exact formats and limits.

The browser retains fractional movement and separates gesture recognition, scrolling momentum, text edits, and transport flow control. No idle decorative frame loop is needed. Detailed layout/gesture behavior is documented in [UI.md](../UI.md); developer tests include deterministic jitter, suspension, release, and weak-link simulations. Synthetic queueing/microbenchmark results in `artifacts/` are diagnostic evidence, not physical radio/cursor measurements.

The Linux input module is the boundary for future operating-system backends. Per-device approval and revocation need a new pairing model; they should not be presented as properties of today's shared bearer credential. Security boundaries and limitations are documented in [SECURITY.md](../SECURITY.md).
