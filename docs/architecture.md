# Architecture

Ghostpad is a standalone Rust receiver with compiled-in HTML, JavaScript, CSS, and icons. The phone connects directly over local HTTP/WebSocket or optional HTTPS/WSS. There are no Cargo registry or browser runtime dependencies. System OpenSSL provides TLS, hashing for the WebSocket handshake/CSP, and constant-time credential comparison. SHA-1 is used only for the RFC 6455 handshake, not for stored credentials.

| Boundary | Implementation |
| --- | --- |
| CLI, bounded HTTP routing, controller ownership | `src/main.rs` |
| Private IPv4 selection and validation | `src/network.rs` |
| Persistent pairing key | `src/pairing.rs` |
| OpenSSL and buffered deadline-based I/O | `src/transport.rs`, `src/crypto.rs` |
| Narrow WebSocket framing | `src/wire.rs` |
| Input decoding and Linux uinput | `src/input.rs`, `src/keys.rs`, `src/touchpad.rs` |
| Embedded phone page and CSP hashes | `src/page.rs` |
| Phone interface and gestures | `web/src/`, `web/index.html` |
| Desktop pairing interface | `web/desktop.html`, `web/src/desktop.ts`, `web/src/desktop.css` |
| User installation and input/firewall helpers | `scripts/`, `packaging/` |

The complete phone interface arrives in one response. CSP hashes allow the embedded script and style content. The separate desktop assets add no phone startup payload. The desktop polls its authenticated status API and lazily retrieves a cached SVG QR generated by `qrencode` over stdin. It pauses polling when hidden or offline and backs off on failures.

In automatic HTTP mode, the desktop keeps a loopback address and Linux routing notifications refresh the private LAN listener. One blocking wait covers both listeners and the network notification socket. Explicit binds and TLS keep a fixed address.

One authenticated phone holds the input mutex. A reconnect from the same tab or an explicit handoff closes the old TCP connection and waits for input cleanup before taking the mutex. Session ownership is checked during admission. At most 16 connection workers block on socket input, with bounded read and write deadlines. The uinput backend creates pointer, keyboard, and native multitouch devices. Typed text maps supported ASCII to physical US keys. Dropping the process removes its virtual devices.

Motion uses binary packets over a reliable ordered WebSocket. The `ghostpad.session.v1` and `ghostpad.flow.v1` subprotocols confirm validated input delivery. Browser flow control coalesces movement within bounded queues, reserves capacity for release and control commands, and expires stalled input. Receivers also accept the original unwrapped protocol. See [PROTOCOL.md](../PROTOCOL.md) for exact formats and limits.

The browser retains fractional movement and separates gesture recognition, scrolling momentum, text edits, and transport flow control. No idle decorative frame loop is needed. Detailed layout/gesture behavior is documented in [UI.md](../UI.md); developer tests include deterministic jitter, suspension, release, and weak-link simulations. Synthetic queueing/microbenchmark results in `artifacts/` are diagnostic evidence, not physical radio/cursor measurements.

The Linux input module is the boundary for future operating-system backends. All controllers authenticate with the receiver's shared pairing key. Security boundaries and limitations are documented in [SECURITY.md](../SECURITY.md).
